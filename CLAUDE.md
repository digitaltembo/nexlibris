# nexlibris

Calibre-like library manager. [PLAN.md](PLAN.md) is forward-facing: the vision, guiding decisions, and what is left per milestone (M1, M4, M6–M12, in planned order; numbers are names, not an order), kept concise; keep it current when scope or decisions change, and drop work once done (git history has it). Its **TLDR** section (status table and next steps) must be updated in the same change whenever work moves a milestone forward. The README describes the architecture.

## Layout

- `common/` (`@nexlibris/common`): the library model, shared by every frontend and backend.
  - `types.ts` schema (an item's `metadata` is a `BookMetadata`: fixed fields such as `titleSort`, `authorSort`, `published`, `originallyPublished`, `language` and `coverColor`, plus any custom keys); `metadata.ts` normalizing its values (partial ISO dates, with a minus for years before AD 1, `-0570` being 570 BC with no year 0; Calibre's midnight-UTC timestamps rounded to the day; numbers), dates for reading and in order (`formatDate`, `formatYear`, `compareDates`; sort and compare dates with these, not as strings) and sort names (`titleSortOf`, `nameSortOf`); `operations.ts` typed operations and the pure `applyOperation` reducer; `backend.ts` `LibraryBackend` and `StoredLibraryBackend` (library JSON + change log + content-addressed files on any `Storage`).
  - `storage.ts` the `Storage` interface, which can delete (`remove`; `MemoryStorage` for tests), and optionally move and prune emptied folders (`moveFile` falls back to copying; `prefixedStorage` a storage's subfolder).
  - `placedLibrary.ts` a library in a folder of the user's (`PlacedLibraryBackend`): its own files in `.nexlibris/` (as `StoredLibraryBackend` keeps them, plus `layout.json` and `placed.json`, where each book file is by hash), the books where a `FileLayout` (path templates) puts them, by a `Placer` the client supplies (`client/src/library/fileLayout.ts`), moved in the background after each change. `servedLibraryPath` is what the desktop app serves by URL. `libraryFolderApi.ts` the desktop app's choosing and moving of the library's folder (desktop only). The backend deletes files with `deleteFile`/`deleteLocalFile`; `client/src/library/freeFiles.ts` deletes the files of deleted books that nothing else uses.
  - `syncApi.ts` M6's sync API (a hub serves it; `pair`, `hello`, `state`, `apply`, `done`, `missing`, plus files streamed at `api/sync/files/<hash>`), `sync.ts` running a sync from the instance that drives it (`previewSync`, `runSync`, `pairWithHub`) and the hub's side (`createSyncService`), `syncHttp.ts` the API and files over `fetch`, `syncFiles.ts` moving files after a sync (`transferFiles`) and fetching missing ones on read (`fetchingMissingFiles`); `syncHostApi.ts` the desktop page's control of hosting (desktop only), `peerApi.ts` Android's relay of sync calls and files (Android only).
  - Other transports, with the phone as hub: `syncMessage.ts` the API's calls as chunked messages (`messageFetch`; the framing is mirrored in `android/.../BluetoothFraming.kt`, keep the two in step), `syncHub.ts` a hub in TypeScript (pairing, calls, files) that the Android page runs for Bluetooth, `bluetoothApi.ts` the GATT UUIDs and Android's bluetoothHost API, `folderHub.ts` a replica library in a shared folder acting as hub (USB), `usbFolderApi.ts` Android's sync folder as storage (Android only).
  - `scope.ts` what a hub shows an instance: only the books its connection picks (a `ScopeRule` the client supplies, `instanceScope`) plus those it has, with everything naming other books cut out of the library and the changes sent. `createSyncService` with a `scope` (network and Bluetooth hubs; not the folder hub) applies it to the peer its host names (`fromPeer`), and refuses deletions from that peer: a book deleted there is kept off it (`Device.excluded`) instead, and books it no longer picks are let go of after their files are sent (`leaveOutside`, `letGo` in `client/src/sync/instances.ts`).
  - `merge.ts` M6's merge of two instances as a pure function (`planMerge`, by targets an operation writes); `repair.ts` the state hash checked after a merge (`stateDigest`) and the repair from the source of truth (`planRepair`). Their tests share a seeded random edit generator; keep both random tests passing.
  - `storageApi.ts` the Storage API defined with estuary-rpc; `saveApi.ts` saving files out of the app; `importApi.ts` native file and folder picking for import (the app stores picked files itself); `rpc.ts` estuary-rpc over a message channel; `rpcStorage.ts` `Storage` over that API (base64 chunks).
- `client/` (`@nexlibris/client`): React + Vite web app.
  - `backends/` OPFS storage (browser) and the Android and desktop bridges. `library/LibraryContext.tsx` picks one: the native app's storage when there's a transport (`backends/native.ts`: Android's bridge or the desktop app's `window.NexlibrisDesktop`), otherwise OPFS. In both apps `NativeStorage` reads stored files by fetching `/library/files/…`, which the app serves; everything else goes over the transport.
  - `formats/` metadata extraction per format (EPUB, MOBI/AZW3, PDF, TXT/RTF, CBZ/CBR; `opf.ts` an OPF's metadata, an EPUB's or a Calibre `metadata.opf`) and `formats/convert/` in-browser conversion. `formats/convert/xteink/` is the CrossPoint X4/X3 optimizer, a port of the Python in `~/dev/crosspoint/calibre-plugins/crosspoint_reader/` (keep it in step with `optimizer.py`/`textsplit.py`); its options live in `xteink/options.ts` and are part of the converter version.
  - `isbn/` ISBN checking, Open Library lookup and barcode reading (native `BarcodeDetector`, else zxing-wasm, whose wasm is bundled rather than fetched from its CDN); the "Add by ISBN" UI is `components/IsbnDialog.tsx`.
  - `devices/` connection plugin points (`types.ts`: a `ConnectionType` is a `DeviceType`, a reader that books are copied to (whose `tools` manage other things on it, each a tab beside its books on the "On it…" screen), a `CatalogType`, an OPDS catalog written out, or an `InstanceType`, another nexlibris the library syncs with), the sync planner/runner (`plan.ts`, `run.ts`; a book whose path changes is moved where the target can, `DeviceTarget.move`, else sent again; files linked by hand, `PlacedFile.linked`, stay put while current; copies of chosen books found on the device, by `devices/match.ts`, are kept or moved into place rather than sent, `PlacedFile.found`), `pathTemplate.ts` where books go on a device (`DeviceType.folder` and `fileName` are templates: `/library/<author>/[<series>/]`, made safe for FAT), `contents.ts` (what's on a connection against the library, with linking, importing and removing: a book removed from a device is taken off the connection, `removeOperations`, kept off it if its search picks it), and `devices/opds/` the OPDS catalog export (calibre3opds's layout) and its remembered folders. The UI calls them connections (`components/ConnectionsDialog.tsx`); the stored model still calls them devices (`library.devices`). `plugins/` built-in plugins, each adding connection types and/or views (`views/types.ts`: a `LibraryViewType`, a way of showing the books beside grid and list, offered by `views/views.tsx` in the switcher, the View menu and Settings) (`bookshelf/`: the CSS 3D bookshelf view; `graph/`: the force graph view, after `~/Documents/readings`, books joined by their authors, tags and series (`graph.ts`, tags on a quarter of the books left out as hubs) and drawn with 3d-force-graph in the theme's colours (`ForceGraph.tsx`, loaded lazily since three.js is large; the glow only in the dark scheme); `nexlibris/`: the instance type; `opds/`: the plain catalog; `crosspoint/`: X4/X3 device and catalog types, the CrossPoint web API client (`client.ts`; `fakeReader.ts` an in-memory reader for tests and stories), its device tools in `tools/` (sleep images, made into screen-sized grayscale BMPs by `sleepImage.ts`; StarDict dictionaries, unpacked and checked by `stardict.ts`; fonts, sorted into families by `fonts.ts`), and `libraryIndex.ts`, the reader's `/.crosspoint/library.idx`, a port of `~/dev/crosspoint/crosspoint-reader/docs/files/library_idx.ksy`: keep it in step with that).
  - `library/libraryFolder.ts` where the library is kept (browser storage, the desktop app's data folder, or a folder the user picks, laid out by `library/fileLayout.ts` with CrossPoint's path templates; not on Android), opening it (`LibraryContext` uses it; a browser asks permission for its folder again with a click) and moving it (`relocate` in the browser, copying between folder handles; the desktop app's main process moves it, `desktop/src/libraryFolder.ts`). The UI is `components/LibraryFolderDialog.tsx` ("Library folder…").
  - `library/importFiles.ts` imports: groups files into books (a Calibre book folder with `metadata.opf`, else by name minus the format), takes a Calibre folder's metadata, cover and rating, and matches books already in the library (UUID, ISBN, title and author). Folders come from a folder input, dropped folders (`library/droppedFiles.ts`), or the apps' folder pick (`library/nativeImport.ts`).
  - `library/thumbnails.ts` covers as shown: thumbnails made once and kept in the backend's local files (`readLocalFile`/`writeLocalFile`, under `local/`; not synced or backed up), at `local/thumbs/`, which the apps serve at `/library/local/thumbs/…` as they serve `/library/files/…`. `components/Cover.tsx` shows a thumbnail only while near the viewport; don't display full-size covers in lists.
  - `library/currentlyReading.ts` Currently Reading: books with a reading position that isn't finished or set aside (`ReadingPosition.setAside`, which keeps the place; reading again clears it), shown by `components/CurrentlyReading.tsx` in a notice above the books (`NoticeBox` in `styles/ui.ts`); one click reopens a book at its place. The notice shows each time the app opens while books are being read, until its Hide (not remembered); the Library lists them too, as Currently reading beside All books and Recent books (`['reading']` in `browse.ts`, last read first unless sorted).
  - `library/bookFields.ts` the fixed fields' labels and kinds as the UI shows and edits them, and the sort keys (title and author sort, falling back to computed ones; first published).
  - `library/coverColor.ts` a cover's most prominent colour (`coverColor`), set at import, on Add by ISBN and by re-reading; `components/Cover.tsx` fills a loading cover with it.
  - `library/dedupe.ts` items with the same title and authors and merging them (as operations); `library/reread.ts` re-reading metadata from the books' own files, filling in only what items lack (never online). `library/updateFiles.ts` writing the library's metadata into its EPUBs where they say otherwise (`writeEpubMetadata` in `formats/epubMetadata.ts`, which also prepares copies for devices; DRM-protected files, `epubDrm`, are left alone), each new file checked to read back as the library has it before it replaces the old one, with converted files, reading positions and the text index (`TextIndex.carry`) moved to it. The UI is `components/CleanupDialog.tsx` ("Clean up library…"), a list of cleanups each behind a button, where further cleanups go.
  - Open Library is called only on explicit user action (Add by ISBN); nothing looks things up online on its own.
  - `library/search.ts` the search syntax (Gmail-style `field:value` terms, `or`, `has:`; documented at its top) used by the search box, filters and device rules; `library/filters.ts` filters as rules (what `components/FiltersDialog.tsx` edits), converted to and from that syntax.
  - `fulltext/` full-text search: `extract.ts` a file's text in sections (EPUB spine items with chapter names and CFI paths per text node, and TXT, read with `markup.ts`, htmlparser2 rather than the DOM, so they work in a worker; PDF pages and RTF in the page, `extractPage.ts`), `match.ts` queries, word lists and passages (each with its chapter and the locator the reader opens at), `textWork.ts` the heavy work run in a Web Worker (`text.worker.ts`, over `workerRpc.ts`; in the page in tests): extracting, packing (gzipped JSON) and searching, with the word lists it has read cached; `textIndex.ts` the index in the backend's local files (`fulltext/<hash>.json.gz` and `.words.json.gz`, listed in local state's `fulltext`; not synced or backed up), `TextIndexContext.tsx` indexing in the background and `useTextSearch`. The search dialog's "Inside books" mode and `components/TextResults.tsx` show it; bump `EXTRACTOR_VERSION` when extraction changes.
  - `catalogs/` browsing OPDS catalogs on servers: a connection of kind `source` (`SourceType` in `devices/types.ts`; `opdsServer` in `plugins/opds/`, beside the OPDS Static Export) that takes no books and has no rules, only "On it…" (`SourceContents` in `ConnectionsDialog.tsx`) and a place in the Library (`['source', id, ...steps]` in `browse.ts`, a step a page's address or `search:<terms>`, named for the breadcrumbs by `titles.ts`). `opdsFeed.ts` parses OPDS 1 feeds and OpenSearch descriptions (keep it general: calibre3opds's static layout, Gutenberg, calibre's server), `feedCache.ts` keeps pages in local files (`opds/<hash>.json`) and checks them with the server after a day (conditional requests where possible), remembers how many pages were loaded (Load more), and searches (the feed's template, else its description's, else the connection's Search address setting; a 404 from a static catalog is no results), `remote.ts` fetches with `fetch` in browsers (CORS permitting; a book that can't be downloaded gets its link instead) and through the desktop main process (`common/src/remoteApi.ts`, `desktop/src/remote.ts`, downloads stored like imports), `credentials.ts` a catalog's sign-in (HTTP Basic), per connection, in local state (`catalog-credentials`; never in the library, so not synced or backed up), sent only to the catalog's own origin; covers that need it are read as blobs (`useCatalogImage.ts`, `fetchSignedInImage`). `addBook.ts` adds a book via `importFiles` and finds the library's copy. `asItem.ts` makes a catalog's books `Item`s (filling `BookMetadata` from what the feed says: series, publisher, language, dates, identifiers, downloads as files), shown only, so `CatalogBrowser.tsx` shows them in the library's own views (grid, list, plugin views), with their covers and an "In library" badge from `components/CollectionDecor.tsx`, which `Cover` and the grid read; a book opens its details and downloads rather than `ItemDetail`. The UI is `components/CatalogBrowser.tsx`; a catalog that offers search is a mode of the search dialog. Catalogs are read only when the user opens a page, adds the connection or asks for more.
  - `library/browse.ts` where the view is: a path from the Library (calibre3opds's navigation: All books, Recent, Currently reading, Authors, Series, the user's `library.categories`, Tags) to books, with the breadcrumbs (`components/Breadcrumbs.tsx`) and the level's entries (`components/BrowseEntries.tsx`); categories are edited in `components/CategoriesDialog.tsx` and written into OPDS catalogs as custom feeds.
  - `sync/` M6 sync in the page: `connect.ts` reaching a pairing's hub by its transport (address prefix `bluetooth:`, `folder:`, else the network), `hub.ts` over the network (Android's relay or `fetch`), `bluetooth.ts` over Web Bluetooth, `bluetoothHost.ts` the Android app hosting over Bluetooth, `folder.ts` through a folder, `files.ts` a hub's files, `instances.ts` other instances as connections, `hosting.ts` answering paired devices in the desktop app (the hosting screens choose which books' files a device keeps before it pairs: the code carries the choice, `PairResult.keepFiles`, which becomes the rules of that device's own connection, `pairedConnections`; and afterwards, `components/KeptBooks.tsx`), `describe.ts` conflicts in words. Another instance is a connection like a reader: a `Device` of type `nexlibris.instance` whose id is that instance's origin, kept in the library and synced, whose books are the ones that instance gets (it sees only those; sync sends the hub its books' files and fetches this instance's). How this instance reaches it (the `Pairing`: address, key, source of truth, sync base) stays in local state. The UI is `components/ConnectionsDialog.tsx`, with pairing, the sync preview and hosting in `components/InstanceSync.tsx`; there's no separate Sync command. `library/savedFolders.ts` remembers picked folders (catalogs, sync folders) in IndexedDB.
  - `stories/` Storybook's sample library (`sampleLibrary.ts`, a fresh in-memory copy per story, with generated covers) and helpers; stories sit next to their components as `*.stories.tsx`. Config in `client/.storybook/`: every story gets `GlobalStyle` and a `LibraryProvider` over the sample library, and the toolbar's Theme picks light or dark.
  - `reader/` in-app viewers (`Reader` over the library; `BookReader`, the viewer needing only the book). In browsers and the desktop app, Read opens the book in a window of its own (`library/readerWindow.ts`): the app's page at `?read=<item>&file=<hash>`, which `main.tsx` renders as `components/ReaderWindow.tsx` alone, without a library; it asks the library's window for the book over a BroadcastChannel (`serveReaderWindows`, run by `App`) and sends it reading positions to save. Android reads over the library. `components/` UI; `styles/` theme and shared styled components.
  - The top bar and the breadcrumbs stay at the top (`Header` in `App.tsx`, sticky; its height is `--header-height`, which the list's column headers stick below); `Main` isolates its stacking so nothing in the books paints over them. The breadcrumbs' far right holds the view switcher (`components/ViewSwitcher.tsx`).
  - The top bar holds only the name and `components/SearchBox.tsx`, which shows the search (with clear and filters buttons) and opens `components/SearchDialog.tsx`, a Spotlight-like search with completions from `library/suggest.ts`, filter chips, recent searches and the first books found; Enter puts the search back in the bar. Commands are defined once in `App.tsx` and shown as `components/AppMenu.tsx`, a left drawer, in browsers and on Android, or as the desktop app's menu bar (`library/nativeMenu.ts`, built natively by `desktop/src/menu.ts` from `common/src/nativeMenu.ts`). Grid/list, sort and columns are in `components/SettingsDialog.tsx`. Add a new command to both menus. Selection follows `library/selection.ts` (click, Cmd/Ctrl-click, Shift-click; a long press on touch screens, `library/useLongPress.ts`); several selected show Bulk edit (`BulkEditor.tsx`; its Files section removes a format's files, `removeFormat` in `library/freeFiles.ts`; a book's own files are removed one at a time in `components/ItemFiles.tsx`, `removeFiles`) and Bulk convert (`BulkConvertDialog.tsx`) in the top bar.
- `android/`: Kotlin WebView shell. Serves `client/dist` from assets at `https://appassets.androidplatform.net` and implements the Storage, Save and Import APIs natively (`StorageService`, `SaveService`, `ImportService`, `RpcRouter`, plus `PeerService` relaying sync calls to a hub, since the page can't call plain http, and moving files between the hub and storage, `BluetoothHostService` a BLE GATT server carrying sync messages for the page to answer, `ImportFolder.kt` walking a folder picked for import, `SyncFolderService`/`DocumentTreeStorage` the user-picked USB sync folder through the storage provider, `NativeBridge`, a `WebViewCompat` web message listener limited to the app's origin); the camera, for ISBN scanning, is granted only to the app's own pages. Library logic stays in TypeScript.
- `desktop/`: Electron shell. Serves `client/dist` at `app://nexlibris/` and implements the Storage, Save and Import APIs in the main process over native files (`fileStorage.ts`, `saveService.ts`, `importService.ts`, served with `createMessageHandler`); the preload exposes `window.NexlibrisDesktop.rpc` for those, plus the menu bar (`setMenu`, `onMenuCommand`; `menu.ts` checks what the page sends and adds the app menu, Quit and Window). On macOS the window has no title bar (`titleBarStyle: 'hiddenInset'`): the preload's `titleBarInset` and `onFullScreen` let the page mark `<html data-title-bar="inset">` (`followTitleBar` in `client/src/backends/desktopBridge.ts`), so the top bar leaves room for the window buttons and moves the window (`-webkit-app-region`), and the reader gets a drag strip; anything covering the top bar (a `dialog`, or `[data-covers-window]`) turns the drag region off. Stored files are read from `app://nexlibris/library/files/…`, as on Android. The library's folder is the data folder's `library`, or one chosen in the app (`settings.json` in the data folder; `libraryFolder.ts` moves it, and `main.ts` switches to it without restarting); in a folder of the user's, the books placed in it are served too, and imports and synced files land in its `.nexlibris/`. A book's window (`isReaderUrl`) is allowed to open as another app window; menu commands and sync calls go to the library's window (`libraryWindow`). As a sync hub, `syncHost.ts` serves the sync API on the LAN and relays calls to the page (the preload's `servePeers`), serving and storing files itself; pairings live in `<library>/local/sync-host.json`. Bundled with rolldown (`dist/main.js`, `dist/preload.cjs`). `npm start -w desktop` runs `scripts/start.js`, which on macOS launches a renamed copy of Electron (`desktop/.app/nexlibris.app`, ignored by git) so the app shows as nexlibris; `productName` in `desktop/package.json` sets the app name and so its data folder.
- `server/`: placeholder for M4.
- `icon.png` is the source of every app icon. After changing it, run `python3 scripts/make-icons.py` (needs Pillow): it writes the squircle favicons (`client/public/`), the desktop icon (`desktop/assets/icon.png`) and the Android launcher icons (`android/.../res/mipmap-*`).

## Commands

Run from the repo root (Node 24 via nvm; in a non-login shell, put `~/.nvm/versions/node/v24*/bin` on PATH).

- `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`, `npm run dev`.
- Storybook: `npm run storybook -w client` (http://localhost:6006), `npm run build-storybook -w client` (to `client/storybook-static/`, ignored by git). Add a story when adding or changing a component; one that needs the library can read it from context, which holds the sample library. Run test, typecheck, lint and build before calling work done.
- Lint is oxlint (`.oxlintrc.json`), not ESLint: typescript-eslint doesn't support TypeScript 7. Rules that only flag idioms used on purpose here are off in the config, with the reason; a one-off exception gets `// oxlint-disable-next-line <rule> -- why`.
- Single workspace: `npm test -w client`, or `npx vitest run src/path` inside a workspace.
- Desktop: `npm run desktop` (builds, then runs Electron). `NEXLIBRIS_LIBRARY_DIR` picks the library folder. npm may skip Electron's install script; then run `node node_modules/electron/install.js`.
- Android: `npm run android`; native tests `cd android && ./gradlew testDebugUnitTest lintDebug`. Needs `JAVA_HOME` set to Android Studio's JBR (the system Java is 8) and `android/local.properties` with `sdk.dir`. Builds use compileSdk 36 and build-tools 36.1.0; newer AndroidX releases need AGP 9 / API 37.

## Conventions

- Mutate libraries only through operations; never edit `Library` objects directly in the UI.
- Changing the stored shape of a library (types in `common/src/types.ts`, or an operation's shape) means bumping `SCHEMA_VERSION` and adding a step to `MIGRATIONS` in `common/src/migrate.ts`, with a test.
- Prefer TypeScript implementations of format parsing and conversion that run in the browser.
- Styling uses styled-components with transient `$props`; theme values are CSS variables in `styles/GlobalStyle.ts`, dark when the system is unless Light or Dark is picked in Settings (`styles/appearance.ts`, `<html data-theme>`); code that needs to know reads `isDark`/`onAppearanceChange` there rather than `prefers-color-scheme`. Reuse `styles/ui.ts` before adding new primitives. No CSS files.
- Book HTML (descriptions, EPUB content) is untrusted: render it with `RichText`, which rebuilds allowlisted tags as React elements. Never use `dangerouslySetInnerHTML`.
- Tests run in happy-dom with resource loading disabled (`client/vite.config.ts`); keep it that way so tests never hit the network. Sample books live in `client/src/formats/fixtures/`. happy-dom differs from browsers: parse XML with `formats/xml.ts` (happy-dom rejects some valid XML declarations), and mock the Kindle parser in import tests (under Node it fetches resources and writes to disk).
- Code style: single quotes, lines around 120 columns (some run longer). There's no formatter config, so don't run Prettier over whole files: it rewraps untouched code. Format only what you write, by hand or on a scratch copy.
- Any change to the Storage, Save or Import API must be made in `common/src/storageApi.ts`/`saveApi.ts`/`importApi.ts`, `android/.../RpcRouter.kt` plus `StorageService.kt`/`SaveService.kt`/`ImportService.kt`, and `desktop/src/fileStorage.ts`/`saveService.ts`/`importService.ts`, with tests on every side. The SyncHost API is desktop-only; the Peer, bluetoothHost and usbFolder APIs are Android-only.
- Save files out of the app with `client/src/library/saveFile.ts`, not `<a download>` alone: downloads do nothing in the Android WebView. For big files use `saveParts` (the backup does, with `library/zip.ts`), and call it before awaiting anything so Chrome's save picker still has the click's user activation.

## Dependencies to know about

- `epubier` is linked from `../epubierjs` (`file:` dependency), which must be checked out next to this repo. nexlibris uses its built `dist/`, so run `npm run build` there after changing it. Its `position` and `onLocationChange` options exist for nexlibris's reading positions, and `replacements: 'base64'` for opening image-heavy books quickly in the Android WebView; `src/patches.js` there fixes epub.js's base64 mode.
- `estuary-rpc` is the published 1.0.6, older than the `~/dev/estuary-rpc` source (no `ApiTypeOf`), which is why `rpc.ts` defines its own client types.
